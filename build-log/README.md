# build-log

The working record of how TinyVault was built. You don't need any of it to use TinyVault.

It was written, over three weeks, for the person and the two coding agents (Claude Code and Codex) doing the work: plans, specs, handoffs, review findings, decisions and session notes. It is long and full of internal shorthand, and it is kept unedited on purpose. Failed runs and rejected reviews are left in.

It was moved here from the repo root and from `docs/` just before launch, to keep those readable. The files keep their old layout relative to each other, so paths written inside older records (`docs/…`, `PLAN.md`) are relative to this folder. Links that pointed outside the record were updated; nothing else was reworded.

Where to start:

- [`PROJECT-SPEC.md`](PROJECT-SPEC.md): the kickoff spec, trimmed at launch.
- [`PLAN.md`](PLAN.md): the current state and the Decisions Log ("X over Y because Z"). [`PLAN-archive.md`](PLAN-archive.md) holds the older detail.
- [`docs/handoff-pattern.md`](docs/handoff-pattern.md): how the two agents split the work and reviewed each other.
- [`docs/README.md`](docs/README.md): an index of every plan, packet, handoff and review register.
- [`ORIENT.md`](ORIENT.md): a one-page re-entry note for a human coming back after time away.
- [`BACKLOG.md`](BACKLOG.md) and [`guides/`](guides/): the idea list and the working guides the agents followed.

A few files from the record stayed in [`../docs/`](../docs/README.md), because the README cites them as evidence or because tests refer to them by path.
