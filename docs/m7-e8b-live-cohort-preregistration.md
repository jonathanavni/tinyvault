## 4. Run accounting

1. **Every run counts.** The 100 pre-declared identities are the cohort; a failed, timed-out, capture-failed or unattested run stays in the record as that failure and is never replaced, re-run, or excluded from the tally.
2. **No replacement runs, no additional cohorts, no partial re-execution** of a cell. If the cohort ends unqualified or the acceptance reading is not met, that is the recorded outcome; any next step is a new user decision with a new pre-registration.
3. **One command execution.** `TINYVAULT_N=10 make eval` is started once. If it dies before minting a cohort (compose-up failure, missing key, pre-flight red), that is recorded as an attempt that did not start; **any spend that occurred is counted** and the attempt is not restarted without the user's word.
4. **Spend ledger.** The pre-registered watcher (§6.3, rev 2 at `artifacts/review-evidence/tinyvault-m7-e8b-20260910/e8b-spend-watcher.sh`; rev 1 at the m8-packet path is superseded) writes a per-minute ledger line `completed_runs counted no_usage unfinished malformed unaccountable in out usd` from the persisted run directories, usage deduplicated by response id; the final ledger is reconciled against the Anthropic Console usage view after the run and both figures are recorded, with any discrepancy stated. A final `unfinished` or `no_usage` count other than 0 is itself reconciled against `runs.json` and stated (a run that ended before any request legitimately has no usage).
5. **Nothing is adjusted mid-run** — no prompt, cap, gate, fixture, environment variable or timeout change once the command has started; the source-drift check would reject the cohort anyway, and a drift red is preserved, not repaired.

### 6.3 The spend watcher (rev 3.1) and launcher (rev 2.1) — pre-registered executables, no repository change

Both live in the gitignored evidence directory `artifacts/review-evidence/tinyvault-m7-e8b-20260910/` with their test suite (`e8b-watcher.test.sh`) and its logs; the rev-1 watcher at the m8-packet path is superseded and kept only as history. The eval never depends on them (they are external monitors of the harness's own artifacts), so no repository file changes and the candidate stays `bac91db`.

**Watcher (rev 3)** — `zsh e8b-spend-watcher.sh <clone-root> 10.00 <eval-pgid> <ledger-path>` (env `E8B_POLL_SECONDS` 60, `E8B_GRACE_SECONDS` 30, `E8B_EXPECTED_RUNS` 100; `PATH` pinned; the threshold is parsed once as a finite positive decimal, `nan`/`inf`/`0`/negative refused). Every poll enumerates `<root>/artifacts/eval/*/runs/*/` explicitly (a missing directory, enumeration error or unreadable file is an error, never "no records") and classifies each run directory: **unfinished** (no `events.json` yet, or exactly the runner's initial `[]` — expected while a run is open); **counted** (non-empty JSON array whose every `sdk-response` event is a `type: message` body with a `msg_` id and non-negative integer token counts); **no_usage** (non-empty, but no `sdk-request-context` and no `sdk-response` event — a run that ended before any request); **malformed** (does not parse — tolerated for one poll because the runner's close write is a plain non-atomic `writeFile`, fatal if the same file is still malformed on the next poll); **unaccountable** (an `sdk-response` that is not a readable message, negative/boolean/non-integer token counts, an unknown `*_tokens` field or non-zero `server_tool_use`, duplicate `msg_` ids that disagree, or a read error — fatal at once, because usage that cannot be accounted must never be silently omitted); **not_started** (`E8B_EXPECTED_RUNS` minus run directories seen — reported). **Usage is taken only from `initiator: sdk-response`, `direction: outbound` events (the SDK's response object); model-emitted text is never parsed as billing data** (verified in the N10 evidence: `model-client-response` carries the content array, `model-client` plain text, `sdk-metadata` only `bodyBytes`; only `sdk-response` carries `id`/`usage`). Deduplicated by `msg_` id. Requests without a response (`sdk-request-context` count > responses) are charged at the planning worst case $0.01312 each and reported as `unanswered`. Prices $1/M in, $5/M out (re-confirmed at pre-flight 6b, `rate-confirmation.md`); cache creation charged at the 1 h write rate $2/M and cache reads at $0.10/M, both reported (`cc=`, `cr=`; the N10 evidence had zero). Ledger line per poll: `UTC completed_runs= counted= no_usage= unfinished= not_started= malformed= unaccountable= unanswered= in= out= cc= cr= usd= threshold_reached=`; the threshold comparison is made inside the accountant (no shell interpolation), and the accountant's output is validated against a full schema before use. A heartbeat file (`spend-ledger.txt.heartbeat`) is written after every poll. Group liveness is `alive` / `dead` / `error` — measured on this macOS, a dead or zombie-only group prints nothing in `ps -g` and fails `kill -0 -- -pgid`; "ps printed nothing but the group still exists" is an inspection failure and is treated as loss of monitoring, not as "gone". Exits: **0** only when the group is gone **and** one settled re-read (`FINAL …`) shows no unfinished, malformed or unaccountable record; **5 `FINAL-LEDGER-INVALID`** when the group is gone but such records remain (their usage is *not* in `usd` — reconcile before any claim); **4 `THRESHOLD-STOP`** when `usd >= 10.00`; **3 `MONITOR-LOST`** on any inability to monitor (missing `artifacts/eval`, accountant failure or malformed output, persistent malformed evidence, unaccountable usage, inspection error, non-numeric inputs, unwritable ledger/heartbeat, or SIGTERM/INT/HUP to the watcher); **6 `GROUP-UNKILLABLE`** if the group is still not dead after SIGTERM, the grace period and 12 SIGKILL attempts (the owner intervenes; the watcher never claims "gone" while the group is confirmed alive). **Every exit that leaves the loop while the group is alive kills it first**, so loss of monitoring stops the eval; the kill routine is defined before any precondition and does not depend on the ledger being writable.
